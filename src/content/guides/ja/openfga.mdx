OpenFGA はオープンソースの認可エンジンである。ドキュメントによれば、そのモデル言語の JSON 形式 (API が受け付ける形式) は "closely tracks the language in the Zanzibar paper" (Zanzibar 論文の言語にほぼ沿っている) とされ、DSL は糖衣構文を加えてその JSON にコンパイルされる ([configuration language](https://openfga.dev/docs/configuration-language))。Incubating 入りを告知した CNCF の投稿によれば、OpenFGA は "was developed by a group of Okta employees, and is the foundation for the Auth0 FGA commercial offering" (Okta の従業員のグループによって開発され、商用サービス Auth0 FGA の基盤となっている) ([CNCF, 2025-11-11](https://www.cncf.io/blog/2025/11/11/openfga-becomes-a-cncf-incubating-project/))。Go で書かれ、ライセンスは Apache-2.0 である ([repository](https://github.com/openfga/openfga))。Auth0 のマネージドサービスは自らを "based on OpenFGA, an open-source project owned by the Cloud Native Computing Foundation" (Cloud Native Computing Foundation が所有するオープンソースプロジェクトである OpenFGA に基づく) と説明している ([Auth0 FGA docs](https://docs.fga.dev/fga))。

## 論文の用語と OpenFGA の用語

OpenFGA のドキュメント自体に "Equivalent Zanzibar Concepts" (対応する Zanzibar の概念) の表がある ([configuration language](https://openfga.dev/docs/configuration-language#equivalent-zanzibar-concepts))。下の表はそれを API とストレージまで広げたものである。

| 論文 | OpenFGA |
| --- | --- |
| 名前空間設定 (§2.3) | 認可モデル内の `type`。DSL または JSON で書く ([configuration language](https://openfga.dev/docs/configuration-language)) |
| リレーションタプル `object#relation@user` (§2.1) | `user`、`relation`、`object` を持つ relationship tuple。例：`user:anne`、`owner`、`doc:readme`。ユーザーセットは `group:eng#member` と書く |
| `_this` (§2.3.1) | `[user, group#member]` のような直接の型制約 (JSON では `this`) |
| `computed_userset` | relation 名をそのまま書く。例：`or owner` |
| `tuple_to_userset` | `viewer from parent` (JSON では `tupleToUserset`) |
| `union` / `intersection` / `exclusion` | `or` / `and` / `but not` (JSON では `union` / `intersection` / `difference`) |
| zookie (§2.4) | なし。クエリは `MINIMIZE_LATENCY` か `HIGHER_CONSISTENCY` を選ぶ ([consistency](https://openfga.dev/docs/interacting/consistency)) |
| Check (§2.4.4) | `Check`、`BatchCheck` |
| Read (§2.4.1) | `Read` |
| Write (§2.4.2) | `Write` |
| Watch (§2.4.3) | `ReadChanges`。継続トークンを使うページ分割されたリスト読み取り ([tuple changes](https://openfga.dev/docs/interacting/read-tuple-changes)) |
| Expand (§2.4.5) | `Expand` |
| 論文の API にないもの | `ListObjects`、`StreamedListObjects`、`ListUsers`。ストア。モデルのバージョン (`WriteAuthorizationModel`、`ReadAuthorizationModel(s)`) |
| Leopard (§3.2.4) | ここで引用したドキュメントには相当するものがない |
| Spanner (§3) | `memory` (デフォルト)、`postgres`、`mysql`、`sqlite` ([configure OpenFGA](https://openfga.dev/docs/getting-started/setup-openfga/configure-openfga)) |

API 名は [`openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto) による。

## 共通の例をモデルとして書く

論文の図 1 は、所有者を編集者に、編集者を閲覧者に、親フォルダの閲覧者をドキュメントの閲覧者にする (§2.3.1)。OpenFGA の DSL では、同じルールが関係ごとに 1 行で書ける：

```text
model
  schema 1.1

type user

type group
  relations
    define member: [user]

type folder
  relations
    define viewer: [user, group#member]

type doc
  relations
    define parent: [folder]
    define owner: [user]
    define editor: [user, group#member] or owner
    define viewer: [user, group#member] or editor or viewer from parent
```

<Callout kind="note" title="バリデータには通していない">

このモデルが使っているのは、2026-11-13 時点で OpenFGA の [configuration language のページ](https://openfga.dev/docs/configuration-language) とメンテナーによる Google Drive のサンプル ([`model.fga`](https://github.com/openfga/sample-stores/blob/main/stores/gdrive/model.fga)) に現れる構文だけである：`model`、`schema 1.1`、`type`、`relations`、`define`、`group#member` を含む型制約、`or`、`from`。OpenFGA CLI や Playground には通していない。

</Callout>

Anne、Beto、Chen のタプル：

| user | relation | object |
| --- | --- | --- |
| `user:anne` | `owner` | `doc:readme` |
| `folder:A` | `parent` | `doc:readme` |
| `user:beto` | `member` | `group:eng` |
| `group:eng#member` | `viewer` | `doc:readme` |
| `user:chen` | `viewer` | `folder:A` |

readme に対する `viewer` のチェックは、各人についてこれらのタプルのどれをたどるか。

## アーキテクチャ

OpenFGA のデプロイは何から成るか。ドキュメントが述べているのは、1 つの SQL データストアの上に並ぶサーバー群である。各サーバーは Check 用のインメモリキャッシュを持てる。本番運用ガイドは "a small pool of servers with high capacity (memory and CPU cores) instead of a big pool of servers, to increase cache hit ratios" (キャッシュヒット率を上げるため、多数のサーバーではなく、大容量 (メモリと CPU コア) の少数のサーバー) を勧めている ([running in production](https://openfga.dev/docs/best-practices/running-in-production))。PostgreSQL ではセカンダリ (リードレプリカ) のデータストアを設定でき、`HIGHER_CONSISTENCY` の読み取りはプライマリに送られる ([configure OpenFGA](https://openfga.dev/docs/getting-started/setup-openfga/configure-openfga))。変更を取り込む側は `ReadChanges` を呼び、継続トークンを保持する ([tuple changes](https://openfga.dev/docs/interacting/read-tuple-changes))。

## zookie なしの一貫性

OpenFGA には zookie がない。ドキュメント自身が "Future work" (今後の課題) の項でそう述べている。論文は "has a feature called `Zookies`" (`Zookies` という機能を持つ) とし、OpenFGA は "is considering a similar feature in future releases" (将来のリリースで同様の機能を検討している) という ([consistency](https://openfga.dev/docs/interacting/consistency))。その代わりに、Read とクエリ系の API は次の 2 つの値のいずれかを受け取る：

| モード | 挙動 ([consistency docs](https://openfga.dev/docs/interacting/consistency)) | 論文での対応物 |
| --- | --- | --- |
| `MINIMIZE_LATENCY` (デフォルト) | "will serve queries from the cache when possible" (可能ならクエリにキャッシュから応答する) | zookie なしのリクエスト："a reasonably recent snapshot" (適度に新しいスナップショット) (§2.4.1) |
| `HIGHER_CONSISTENCY` | "will skip the cache and query the database directly" (キャッシュを飛ばしてデータベースに直接問い合わせる) | 厳密な対応物はない。最も近いのは最新のスナップショットでの評価 |

キャッシュは "disabled by default" (デフォルトで無効) であり、その場合 "all queries will have strong consistency regardless of the consistency mode specified" (指定した一貫性モードにかかわらず、すべてのクエリが強い一貫性を持つ) ([consistency](https://openfga.dev/docs/interacting/consistency))。モードが意味を持つのは、キャッシュを有効にしてからである。

キャッシュを有効にしている場合、Chen はフォルダ A から外された直後にも readme を見られるか。

ドキュメントはリクエストごとに判断することを勧めている。アプリケーションがリソースの最終更新時刻を保存していれば、その時刻をキャッシュの TTL と比べて 2 つのモードを選び分けられる ([consistency](https://openfga.dev/docs/interacting/consistency))。そのタイムスタンプは、アプリケーション側が保持する形で zookie の役割の一部を担う。キャッシュ無効化のフラグ (`cache-controller-enabled`) もあり、ストアへの最近の書き込みを確認する。

## 論文との違い

- **zookie がない。** 一貫性トークンを返すことも受け取ることもない。2 つのモードと、デフォルトで無効なキャッシュがその代わりになる ([consistency](https://openfga.dev/docs/interacting/consistency))。論文の一貫性モデルは zookie の上に成り立っている (§2.2)。
- **変更はポーリングで取る。** `ReadChanges` は "sorted by ascending time" (時刻の昇順に並んだ) タプル変更の 1 ページを、継続トークンとともに返す ([`openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto))。論文の Watch はハートビート zookie を伴うストリームである (§2.4.3)。
- **ストレージ。** 論文は Spanner を使う (§3.1)。OpenFGA は `memory` (デフォルト。"Data is lost between server restarts" (サーバーを再起動するとデータは失われる))、PostgreSQL (省略可能なリードレプリカ付き)、MySQL、SQLite を提供する ([configure OpenFGA](https://openfga.dev/docs/getting-started/setup-openfga/configure-openfga))。
- **条件。** `[user with non_expired_grant]` のような型制約により、CEL の条件が成り立つときだけタプルが有効になる ([conditions](https://openfga.dev/docs/modeling/conditions))。論文のタプル (§2.1) には条件がない。
- **contextual tuple。** 単一の Check、ListObjects、ListUsers、Expand リクエストとともに送られ、"not persisted in the datastore" (データストアには永続化されない) タプルである ([concepts](https://openfga.dev/docs/concepts)、[contextual tuples](https://openfga.dev/docs/interacting/contextual-tuples))。
- **ワイルドカード。** `[user, user:*]` で公開の付与ができる ([configuration language](https://openfga.dev/docs/configuration-language))。論文のタプル文法にワイルドカードはない (§2.1)。
- **ストアとモデルのバージョン。** ストアは "one or more versions of an authorization model" (認可モデルの 1 つ以上のバージョン) とそのタプルを保持し、"Store data cannot be shared across stores" (ストアのデータはストア間で共有できない) ([concepts](https://openfga.dev/docs/concepts))。論文では、設定は名前空間 ID をキーとするテーブルに、設定更新の変更ログと並べて格納され、各リクエストは 1 つの設定スナップショットのタイムスタンプで評価される (§3.1.3、§3.2.2)。OpenFGA のチェックは、使うモデルのバージョンを指定できる。
- **Leopard がない。** ここで引用したドキュメントが記述しているのは Check キャッシュとイテレータキャッシュであり、Leopard のような事前計算された集合インデックスではない (§3.2.4)。
- **リスト系 API。** `ListObjects`、`StreamedListObjects`、`ListUsers` は論文の API (§2.4) の外にある。

## ステータス

2026-11-13 時点：開発継続中。最新リリースは 2026-10-28 の v1.22.1、最初のリリースは 2022-06-10 の v0.1.0。GitHub のスターは約 6.1k、ライセンスは Apache-2.0 ([repository](https://github.com/openfga/openfga)、[releases](https://github.com/openfga/openfga/releases))。

- 2022 年 6 月：オープンソース化 ([project post, 2026-01-07](https://openfga.dev/blog/incubation-announcement))。
- 2022 年：CNCF Sandbox プロジェクトとして採択。日付は出典によって食い違う。CNCF のプロジェクトページは OpenFGA が "was accepted to CNCF on September 14, 2022" (2022 年 9 月 14 日に CNCF に採択された) とし、CNCF の告知は 2022 年 9 月としているが、プロジェクト自身の投稿は 2022 年 12 月としている ([CNCF project page](https://www.cncf.io/projects/openfga/)、[CNCF](https://www.cncf.io/blog/2025/11/11/openfga-becomes-a-cncf-incubating-project/)、[project post](https://openfga.dev/blog/incubation-announcement))。
- 2025-10-28：CNCF のプロジェクトページによれば、Incubating の成熟度レベルに移行。
- 2025-11-11：CNCF が、その Technical Oversight Committee が "has voted to accept OpenFGA as a CNCF incubating project" (OpenFGA を CNCF の incubating プロジェクトとして受け入れることを投票で決めた) と告知 ([CNCF](https://www.cncf.io/blog/2025/11/11/openfga-becomes-a-cncf-incubating-project/))。
- マネージドサービスは Auth0 FGA である ([docs](https://docs.fga.dev/fga))。
