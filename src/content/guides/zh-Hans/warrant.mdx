Warrant 是一个用 Go 编写的授权服务。其 README 将其描述为 "a relationship based access control (ReBAC) engine (inspired by Google Zanzibar)"（一个基于关系的访问控制（ReBAC）引擎（受 Google Zanzibar 启发）），同时也涵盖基于角色和基于属性的规则，并把一条关系写作 `[user:1] is an [editor] of [document:docA]`（[README](https://github.com/warrant-dev/warrant)）。一条已存储的关系称为一个 *warrant*。

WorkOS 于 2024 年收购了 Warrant。日期 2024-04-23 来自 WorkOS 在 X 上的一条帖子（[帖子](https://x.com/WorkOS/status/1782774170146791776)）：X 没有向本站的检查程序提供该页面，因此日期是从帖子 ID 解码得出的，而帖子的文字（"Today, we are excited to announce the acquisition of @warrant_dev"，今天，我们很高兴宣布收购 @warrant_dev）只在搜索结果中见到。没有找到 WorkOS 官方的博客文章。Warrant 网站现在写着 "Warrant —> Now WorkOS FGA"（Warrant —> 现为 WorkOS FGA）（[warrant.dev](https://warrant.dev)），README 也链接到 WorkOS FGA 的文档。

## 论文与 Warrant 对照

Warrant 的文档网站已经不在了，因此下表依据开源代码整理。

| 论文中 | Warrant 中（开源版） |
| --- | --- |
| 命名空间配置（§2.3） | 一个对象类型：包含 `type` 和 `relations` 的 JSON，每个关系是一条规则（[spec.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)） |

## 用对象类型表示贯穿示例

论文的图 1 使所有者成为编辑者，编辑者成为查看者，父文件夹的查看者成为文档的查看者（§2.3.1）。在 Warrant 中，每个对象类型列出其关系；空对象 `{}` 表示“仅直接 warrant”，`inheritIf` 则添加一条规则。

```json
[
  { "type": "group", "relations": { "member": {} } },
  { "type": "folder", "relations": { "viewer": {} } },
  {
    "type": "doc",
    "relations": {
      "parent": {},
      "owner": {},
      "editor": { "inheritIf": "owner" },
      "viewer": {
        "inheritIf": "anyOf",
        "rules": [
          { "inheritIf": "editor" },
          { "inheritIf": "viewer", "ofType": "folder", "withRelation": "parent" }
        ]
      }
    }
  }
]
```

这里没有 `user` 条目：服务器在其初始数据库迁移中创建了一个内置的 `user` 对象类型（[迁移](https://github.com/warrant-dev/warrant/blob/main/migrations/datastore/postgres/000002_create_default_obj_types.up.sql)）。带有 `ofType` 和 `withRelation` 的规则找到 warrant `doc:readme#parent@folder:…`，并在找到的每个文件夹上检查 `viewer`，与检查代码中的做法一致（[check/service.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/check/service.go) 中的 `getMatchingSubjectsBySubjectType`）。

<Callout title="对照代码核对，未实际运行">
这些对象类型遵循截至 2026-11-13 开源服务器所接受的结构：[spec.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go) 中的 `RelationRule` 类型，以及维护者的测试夹具，例如 [tests/v2/authz.json](https://github.com/warrant-dev/warrant/blob/main/tests/v2/authz.json)。它们没有被发送到任何 Warrant 服务器。延续 Warrant 的产品 WorkOS FGA 的配置方式不同（见“状态”）。
</Callout>

贯穿示例的五个 warrant，写成 `POST /v2/warrants` 的请求体：

```json
{ "objectType": "doc", "objectId": "readme", "relation": "owner", "subject": { "objectType": "user", "objectId": "anne" } }
{ "objectType": "group", "objectId": "eng", "relation": "member", "subject": { "objectType": "user", "objectId": "beto" } }
{ "objectType": "doc", "objectId": "readme", "relation": "viewer", "subject": { "objectType": "group", "objectId": "eng", "relation": "member" } }
{ "objectType": "doc", "objectId": "readme", "relation": "parent", "subject": { "objectType": "folder", "objectId": "A" } }
{ "objectType": "folder", "objectId": "A", "relation": "viewer", "subject": { "objectType": "user", "objectId": "chen" } }
```

- 一个 Go 服务提供 HTTP API（[router.go](https://github.com/warrant-dev/warrant/blob/main/pkg/service/router.go)）。
- MySQL 和 PostgreSQL 配置接受一个 `dsn` 和一个可选的 `readerDsn`（[config.go](https://github.com/warrant-dev/warrant/blob/main/pkg/config/config.go)）；也支持 SQLite，"in-memory or file"（内存或文件）（[README](https://github.com/warrant-dev/warrant)）。
- 选择连接池的规则写在 [sql.go](https://github.com/warrant-dev/warrant/blob/main/pkg/database/sql.go) 的一条注释中：如果调用是写入、没有只读库、上下文 "contains 'latest' wookie"（包含 “latest” wookie），或者服务器内部代码设置了写库覆盖，就使用写库；否则使用只读库。

## 一致性

Warrant 的代码把它的令牌称为 *wookie*（[wookie](https://github.com/warrant-dev/warrant/tree/main/pkg/wookie)）。`Token` 类型包含一个 ID、一个版本号和一个时间戳，但开源服务器从不把它发送给客户端：warrant 服务在该位置返回 `nil`，HTTP 处理程序也忽略它（[warrant/service.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/service.go)，[warrant/handlers.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/handlers.go)）。服务器真正读取的是请求头 `Warrant-Token`，而且只有一个值会改变行为：`latest`。

README 本身说，在高吞吐量下实现低延迟 "requires running Warrant as a distributed service with the use of Warrant-Tokens (also referred to as Zookies in Google Zanzibar)"（需要把 Warrant 作为分布式服务运行并使用 Warrant-Token（在 Google Zanzibar 中也称为 Zookie）），并说 "this open source version of Warrant is only capable of handling low-to-moderate throughput"（这个开源版本的 Warrant 只能处理低到中等的吞吐量）（[README](https://github.com/warrant-dev/warrant)，厂商撰写）。它关于 Warrant-Token 的链接现在指向 WorkOS FGA 的总体概述，而该概述并没有描述这些令牌。

注意与论文的区别。zookie 设定的是一个下界，使 Zanzibar 可以 "to choose any timestamp fresher than the one encoded in a zookie"（选择任何比 zookie 中编码的时间戳更新的时间戳），并 "at a default staleness with already replicated data"（以默认陈旧度、使用已复制的数据）处理大多数检查（§2.2）。`latest` 中没有任何时间点：它把读取转移到主库，主库是最新的副本，但放弃了只读副本。

## 与论文的差异

- 开源服务器中**没有快照令牌**，如上所述。
- **内置 RBAC 和 ABAC。** 内置了角色、权限、租户、价格档位和功能的对象类型，以及 warrant 上的策略条件（[README](https://github.com/warrant-dev/warrant)，[迁移](https://github.com/warrant-dev/warrant/blob/main/migrations/datastore/postgres/000002_create_default_obj_types.up.sql)）。
- **一种查询语言。** `GET /v2/query` 回答论文中 Read 和 Expand 回答不了的列表类问题（[query handlers](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/query/handlers.go)）。
- **没有 Watch、Expand 或 Leopard**，并且用单个 SQL 主库代替了 Spanner（§3.1）。
