有几个开源项目称自己受到 Zanzibar 启发或以其为蓝本。本页把其中六个与论文逐项对照，每张表对应一个方面。单元格都很简短；每一行的来源都列在各表下方。事实于 2026-11-13 核对，来自各项目自己的仓库和文档，因此大多由厂商撰写。

这六个是：[SpiceDB](https://github.com/authzed/spicedb)（AuthZed）、[OpenFGA](https://github.com/openfga/openfga)（CNCF）、[Permify](https://github.com/Permify/permify)（FusionAuth）、[Ory Keto](https://github.com/ory/keto)（Ory）、[Topaz](https://github.com/aserto-dev/topaz)（Aserto 结束运营之后由其维护者维护）和 [Warrant](https://github.com/warrant-dev/warrant)（WorkOS）。每个都有单独的页面：[SpiceDB](../spicedb/)、[OpenFGA](../openfga/)、[Permify](../permify/)、[Ory Keto](../ory-keto/)、[Topaz](../topaz/)、[Warrant](../warrant/)。

## Schema 语言

论文称之为命名空间配置：带有用户集重写规则的关系（§2.3）。图 1 用一种类似 protocol buffer 的文本语法写出了一个配置；论文没有说明该格式的名称。

| 系统 | Schema 语言 | 格式 |
| --- | --- | --- |
| 论文 | 命名空间配置 | 图 1 中类似 Protobuf 的文本（未说明格式名称） |
| SpiceDB | Schema（`definition`、`relation`、`permission`） | 自有语言 |
| OpenFGA | 授权模型（`type`、`define`） | DSL，编译为 JSON |
| Permify | Permify Schema（`entity`、`relation`、`permission` / `action`、`attribute`、`rule`） | 自有语言 |
| Ory Keto | Ory Permission Language（OPL） | TypeScript 子集 |
| Topaz | Manifest（`types`、`relations`、`permissions`） | YAML，`version: 3` |
| Warrant | 对象类型（`inheritIf`、`rules`） | JSON |

来源：[SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA configuration language](https://openfga.dev/docs/configuration-language) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## 元组语法

论文把元组写作 `object#relation@user`，其中用户本身可以是一个用户集 `object#relation`（§2.1）。在文档给出了字符串形式的地方，下面各行展示 Beto 所在的组是 readme 的查看者。

| 系统 | 名称 | 形式 |
| --- | --- | --- |
| 论文 | Relation tuple（关系元组） | `doc:readme#viewer@group:eng#member` |
| SpiceDB | Relationship | `doc:readme#viewer@group:eng#member` |
| OpenFGA | Relationship tuple | user `group:eng#member`，relation `viewer`，object `doc:readme` |
| Permify | Relational tuple | `doc:readme#viewer@group:eng#member` |
| Ory Keto | Relation tuple | `Doc:readme#viewers@Group:eng#members` |
| Topaz | Relation | 字段 `object_type`、`object_id`、`relation`、`subject_type`、`subject_id`，可选 `subject_relation` |
| Warrant | Warrant | `[user:1] is an [editor] of [document:docA]`（README 中的示例） |

来源：[SpiceDB relationships](https://authzed.com/docs/spicedb/concepts/relationships) · [OpenFGA concepts](https://openfga.dev/docs/concepts) · [Permify sync data](https://fusionauth.io/permify-docs/getting-started/sync-data) · [Ory Keto relation tuples](https://www.ory.com/docs/keto/concepts/relation-tuples) · [Topaz `common.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/common/v3/common.proto) · [Warrant README](https://github.com/warrant-dev/warrant)

## 重写运算符

论文的重写规则用并集、交集和排除组合三种叶节点 `_this`、`computed_userset` 和 `tuple_to_userset`（§2.3.1）。

| 系统 | 并集 / 交集 / 排除 | computed_userset | tuple_to_userset |
| --- | --- | --- | --- |
| 论文 | `union` / `intersection` / `exclusion` | `computed_userset` | `tuple_to_userset` |
| SpiceDB | `+` / `&` / `-` | 写出一个关系或权限的名称 | `parent->view`（还有 `.any()`；`.all()` 取交集） |
| OpenFGA | `or` / `and` / `but not` | 直接写关系名 | `viewer from parent` |
| Permify | `or` / `and` / `not` | 直接写名称 | 点号：`org.admin` |
| Ory Keto | `\|\|` / `&&` / `!` | `this.permits.x(ctx)` | `.traverse(...)` |
| Topaz | `\|` / `&` / `-` | 写出一个关系或权限的名称 | `parent->can_read` |
| Warrant | `anyOf` / `allOf` / `noneOf` | `inheritIf` | `ofType` + `withRelation` |

来源：[SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA equivalent Zanzibar concepts](https://openfga.dev/docs/configuration-language#equivalent-zanzibar-concepts) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## 一致性令牌与模式

论文的 zookie 是 "an opaque byte sequence encoding a globally meaningful timestamp"（一个不透明的字节序列，编码了一个具有全局意义的时间戳）（§2.4）；检查在一个不早于其所携带 zookie 的快照上评估（§2.2、§2.4.4）。

| 系统 | 令牌 | 模式或行为 |
| --- | --- | --- |
| 论文 | zookie | 带 zookie：至少一样新；不带："a reasonably recent snapshot"（一个合理较新的快照）（§2.4.1） |
| SpiceDB | ZedToken | `minimize_latency`、`at_least_as_fresh`、`at_exact_snapshot`、`fully_consistent` |
| OpenFGA | 无 | `MINIMIZE_LATENCY`（默认）、`HIGHER_CONSISTENCY`；缓存默认关闭 |
| Permify | Snap Token | 由 Write 返回，作为 `snap_token` 传给 Check；不带时使用最新的事务 |
| Ory Keto | `snaptoken` 字段 | "not implemented yet and has no effect"（尚未实现，没有任何效果） |
| Topaz | 文档中没有 | reader API 中没有令牌字段 |
| Warrant | `Warrant-Token` 请求头 | 开源服务器不返回令牌，只对 `latest` 作出反应，即把读取发往主数据库 |

来源：[SpiceDB consistency](https://authzed.com/docs/spicedb/concepts/consistency) · [OpenFGA consistency](https://openfga.dev/docs/interacting/consistency) · [Permify snap tokens](https://fusionauth.io/permify-docs/operations/snap-tokens) · [Keto `check_service.proto`](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto) · [Topaz `reader.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/reader/v3/reader.proto) · [Warrant `wookie.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/wookie/wookie.go)、[`sql.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/database/sql.go)、[`warrant/service.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/service.go)

注意，只有两条实线连接能让应用表达“至少与我的写入一样新”，而这正是论文中防范 new enemy 问题的手段（§2.2）。

## Watch 与变更日志

论文的 Watch 以流的形式发送来自变更日志的元组变更，并带有用于恢复的心跳 zookie（§2.4.3、§3）。

| 系统 | API | 形式 |
| --- | --- | --- |
| 论文 | Watch | 流，可用 zookie 恢复 |
| SpiceDB | `Watch` | 流，可用 ZedToken 恢复（`changes_through`） |
| OpenFGA | `ReadChanges` | 带续传令牌的分页读取（轮询） |
| Permify | `Watch` | 流（`stream WatchResponse`） |
| Ory Keto | 无 | 协议文件中没有 watch 服务 |
| Topaz | 无 | 协议文件中没有 watch 服务 |
| Warrant | 无 | 仓库中没有变更或事件端点 |

来源：[SpiceDB `watch_service.proto`](https://github.com/authzed/api/blob/main/authzed/api/v1/watch_service.proto) · [OpenFGA `openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto) · [Permify `service.proto`](https://github.com/Permify/permify/blob/master/proto/base/v1/service.proto) · [Keto protos](https://github.com/ory/keto/tree/master/proto/ory/keto) · [Topaz go-directory protos](https://github.com/aserto-dev/go-directory/tree/main/proto/aserto/directory) · [Warrant 仓库](https://github.com/warrant-dev/warrant)

## 类似 Leopard 的索引

Leopard 是论文中面向大型和深度嵌套组的索引，根据快照和 Watch 更新构建（§3.2.4）。

| 系统 | 预先计算的索引 | 备注 |
| --- | --- | --- |
| 论文 | Leopard | 服务、离线和增量三部分（§3.2.4） |
| SpiceDB | AuthZed Materialize | 商业功能，面向 AuthZed Dedicated 客户；"takes inspiration from the Leopard index component"（从 Leopard 索引组件中获得灵感） |
| OpenFGA | 文档中没有 | 检查缓存和迭代器缓存 |
| Permify | 文档中没有 | "process-local cache; there is no shared cache layer"（进程内缓存；没有共享缓存层） |
| Ory Keto | 文档中没有 | |
| Topaz | 文档中没有 | |
| Warrant | 文档中没有 | |

来源：[AuthZed Materialize](https://authzed.com/docs/materialize/getting-started/overview) · [OpenFGA consistency（缓存参数）](https://openfga.dev/docs/interacting/consistency) · [Permify cache](https://fusionauth.io/permify-docs/operations/cache) · [Ory Keto 文档](https://www.ory.com/docs/keto) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant 仓库](https://github.com/warrant-dev/warrant)。“文档中没有”是指所列页面没有描述这样的索引，而不是已经排除了它的存在。

## 存储

论文把元组、配置和变更日志存储在 Spanner 中（§3、§3.1）。

| 系统 | 数据存储 |
| --- | --- |
| 论文 | Spanner |
| SpiceDB | CockroachDB、Cloud Spanner、PostgreSQL、MySQL（不推荐）、memdb（开发用） |
| OpenFGA | memory（默认）、PostgreSQL、MySQL、SQLite |
| Permify | PostgreSQL、memory |
| Ory Keto | PostgreSQL、MySQL、CockroachDB、SQLite（不用于生产） |
| Topaz | 嵌入式 BoltDB |
| Warrant | MySQL、PostgreSQL、SQLite |

来源：[SpiceDB datastores](https://authzed.com/docs/spicedb/concepts/datastores) · [Configure OpenFGA](https://openfga.dev/docs/getting-started/setup-openfga/configure-openfga) · [Permify configuration](https://fusionauth.io/permify-docs/setting-up/configuration) · [Ory deployment](https://www.ory.com/docs/oss/deployment) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant migrations](https://github.com/warrant-dev/warrant/tree/main/migrations/datastore)
