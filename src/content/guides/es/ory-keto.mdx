Ory Keto es un servidor de permisos escrito en Go por Ory Corp. Su README lo llama "an open source implementation of 'Zanzibar: Google's Consistent, Global Authorization System'" (una implementación de código abierto de “Zanzibar: Google's Consistent, Global Authorization System”) ([README](https://github.com/ory/keto)). Ory también lo ofrece como servicio gestionado: "Ory Permissions is powered by the open source Ory Keto" (Ory Permissions funciona con el Ory Keto de código abierto) en Ory Network (mismo README).

Keto no nació como un sistema Zanzibar. El diseño de Zanzibar llegó en la v0.6.0-alpha.1 el 2021-04-07; las notas de la versión dicen que el Keto anterior pasó a una rama `legacy-0.5` y que "the architectures are vastly different" (las arquitecturas son muy distintas) ([notas de la versión](https://github.com/ory/keto/releases/tag/v0.6.0-alpha.1)). Las reescrituras de usersets, escritas en el Ory Permission Language, llegaron después, en la v0.10.0-alpha.0 el 2022-09-27 ([notas de la versión](https://github.com/ory/keto/releases/tag/v0.10.0-alpha.0)).

## El artículo y Keto, uno al lado del otro

| En el artículo | En Ory Keto |
| --- | --- |
| Configuración del espacio de nombres (§2.3) | Una `class` que `implements Namespace` en el Ory Permission Language (OPL), un subconjunto de TypeScript ([referencia de OPL](https://www.ory.com/docs/keto/reference/ory-permission-language)) |
| Tupla de relación `object#relation@user` (§2.1) | `namespace:object#relation@subject`, por ejemplo `Group:eng#members@User:beto` ([relation tuples](https://www.ory.com/docs/keto/concepts/relation-tuples), [parser](https://github.com/ory/keto/blob/master/ketoapi/enc_string.go)) |
| `_this` | `this.related.viewers.includes(ctx.subject)` |
| `computed_userset` | `this.permits.edit(ctx)`: "A permission can call another permission defined on the same namespace" (un permiso puede llamar a otro permiso definido en el mismo espacio de nombres) |
| `tuple_to_userset` | `this.related.parents.traverse((p) => p.permits.view(ctx))` |
| Unión, intersección, exclusión | `\|\|`, `&&`, `!` |
| Zookie (§2.2, §2.4) | Existen campos `snaptoken` en la API, pero cada uno está "not implemented yet and has no effect" (aún no implementado y sin efecto) ([check_service.proto](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto)) |
| Check (§2.4.4) | `CheckService.Check`, `BatchCheck` |
| Read (§2.4.1) | `ReadService.ListRelationTuples` ([read_service.proto](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/read_service.proto)) |
| Write (§2.4.2) | `WriteService.TransactRelationTuples`, `DeleteRelationTuples` ([write_service.proto](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/write_service.proto)) |
| Watch (§2.4.3) | Ninguno en la API |
| Expand (§2.4.5) | `ExpandService.Expand` ([expand_service.proto](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/expand_service.proto)) |
| Leopard (§3.2.4) | Sin equivalente documentado |
| Spanner (§3.1) | PostgreSQL, MySQL o CockroachDB; SQLite solo para desarrollo ([guía de producción](https://www.ory.com/docs/keto/guides/production)) |

## El ejemplo de referencia en OPL

La Figura 1 del artículo hace que los propietarios sean editores, los editores lectores, y los lectores de la carpeta padre lectores del documento (§2.3.1). En OPL, cada espacio de nombres es una clase: `related` declara las relaciones y los tipos de sujeto que aceptan, y `permits` contiene funciones que devuelven verdadero o falso para `ctx.subject`.

```ts
import { Namespace, SubjectSet, Context } from "@ory/keto-namespace-types"

class User implements Namespace {}

class Group implements Namespace {
  related: {
    members: User[]
  }
}

class Folder implements Namespace {
  related: {
    viewers: (User | SubjectSet<Group, "members">)[]
  }

  permits = {
    view: (ctx: Context): boolean => this.related.viewers.includes(ctx.subject),
  }
}

class Doc implements Namespace {
  related: {
    parents: Folder[]
    owners: User[]
    editors: (User | SubjectSet<Group, "members">)[]
    viewers: (User | SubjectSet<Group, "members">)[]
  }

  permits = {
    edit: (ctx: Context): boolean =>
      this.related.owners.includes(ctx.subject) ||
      this.related.editors.includes(ctx.subject),

    view: (ctx: Context): boolean =>
      this.related.viewers.includes(ctx.subject) ||
      this.permits.edit(ctx) ||
      this.related.parents.traverse((p) => p.permits.view(ctx)),
  }
}
```

`SubjectSet<Group, "members">` es el tipo de OPL para “los miembros de un grupo”, el userset del artículo. Las relaciones son siempre arrays porque "an object can have many subjects" (un objeto puede tener muchos sujetos) ([referencia de OPL](https://www.ory.com/docs/keto/reference/ory-permission-language)).

Esta configuración sigue la sintaxis documentada a 2026-11-13: la [referencia de OPL](https://www.ory.com/docs/keto/reference/ory-permission-language), la [especificación de OPL](https://github.com/ory/keto/blob/master/docs/ory_permission_language_spec.md) del repositorio y el ejemplo de los mantenedores [namespaces.keto.ts](https://github.com/ory/keto/blob/master/contrib/rewrites-example/namespaces.keto.ts). No se ha cargado en Keto.
</Callout>

Las cinco tuplas del ejemplo de referencia, en la forma textual de Keto. Un sujeto escrito como `User:anne` es un subject set con una relación vacía; las tuplas de ejemplo de los mantenedores escriben así a los usuarios ([tuples.json](https://github.com/ory/keto/blob/master/contrib/rewrites-example/relation-tuples/tuples.json)).

```text
Doc:readme#owners@User:anne
Group:eng#members@User:beto
Doc:readme#viewers@Group:eng#members
Doc:readme#parents@Folder:A
Folder:A#viewers@User:chen
```

- Cada contenedor sirve una Read API (puerto predeterminado 4466), una Write API (4467) y una API de sintaxis de OPL (4469), cada una por HTTP y gRPC ([esquema de configuración](https://github.com/ory/keto/blob/master/embedx/config.schema.json)).

(no hay requisitos adicionales para escalar cuando se aloja Ory Keto por cuenta propia: ¡basta con levantar otro contenedor!) (misma guía). Los contenedores comparten la base de datos.

## Consistencia

El zookie del artículo permite a un cliente pedir una comprobación "at a consistent snapshot no earlier than the given zookie" (en una instantánea consistente no anterior al zookie dado) (§2.4.4). La API protobuf de Keto recoge la misma idea en los nombres de sus campos: `snaptoken` en Check, Expand y ListRelationTuples, `snaptokens` en TransactRelationTuples, y un indicador `latest` para una comprobación de cambio de contenido. Todos estos campos están documentados como "not implemented yet and has no effect" (aún no implementado y sin efecto) ([check_service.proto](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto)).

## Diferencias con el artículo

- **Sin zookies.** Los campos existen; el comportamiento, no (véase más arriba).
- **Sin Watch.** La API v1alpha2 tiene servicios Check, Expand, Read, Write, Namespaces y Version, y un servicio de sintaxis de OPL aparte (`opl/v1alpha1`), pero ningún flujo de cambios ([directorio de protos](https://github.com/ory/keto/tree/master/proto/ory/keto)). El Watch del artículo alimenta los índices secundarios y Leopard (§2.4.3, §3.2.4).
- **Sin Leopard.** No se documenta ningún índice de conjuntos desnormalizado.
- **Una sintaxis de lenguaje de programación.** OPL es un subconjunto de TypeScript para que "users can get context help from their IDE" (los usuarios puedan obtener ayuda contextual de su IDE) ([especificación de OPL](https://github.com/ory/keto/blob/master/docs/ory_permission_language_spec.md)). La Figura 1 del artículo escribe una configuración en una sintaxis de texto al estilo de protocol buffers (§2.3.1); el artículo no nombra el formato.
- **Almacenamiento SQL.** Una base de datos SQL compartida en lugar de Spanner (§3.1).
- **Profundidad de la comprobación.** Las solicitudes Check llevan un `max_depth`, "The maximum depth to search for a relation" (la profundidad máxima hasta la que buscar una relación) ([check_service.proto](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto)).
