有數個開源專案自稱受到 Zanzibar 啟發或以其為範本。本頁將其中六個與論文並列對照，每張表一個議題。表格內容簡短；每一列的出處都列在各表下方。事實查核於 2026-11-13 進行，資料來自各專案自己的儲存庫與文件，因此大多由廠商撰寫。

這六個是：[SpiceDB](https://github.com/authzed/spicedb)（AuthZed）、[OpenFGA](https://github.com/openfga/openfga)（CNCF）、[Permify](https://github.com/Permify/permify)（FusionAuth）、[Ory Keto](https://github.com/ory/keto)（Ory）、[Topaz](https://github.com/aserto-dev/topaz)（Aserto 結束營運後由其維護者維護）與 [Warrant](https://github.com/warrant-dev/warrant)（WorkOS）。每一個都有自己的頁面：[SpiceDB](../spicedb/)、[OpenFGA](../openfga/)、[Permify](../permify/)、[Ory Keto](../ory-keto/)、[Topaz](../topaz/)、[Warrant](../warrant/)。

## schema 語言

論文稱之為命名空間設定：帶有使用者集合改寫規則的關係（§2.3）。圖 1 以一種類似 protocol buffer 的文字語法寫出一份設定；論文沒有說明這種格式的名稱。

| 系統 | schema 語言 | 格式 |
| --- | --- | --- |
| 論文 | 命名空間設定 | 圖 1 中類似 Protobuf 的文字（未說明格式名稱） |
| SpiceDB | Schema（`definition`、`relation`、`permission`） | 自有語言 |
| OpenFGA | 授權模型（`type`、`define`） | DSL，編譯為 JSON |
| Permify | Permify Schema（`entity`、`relation`、`permission`／`action`、`attribute`、`rule`） | 自有語言 |
| Ory Keto | Ory Permission Language（OPL） | TypeScript 子集 |
| Topaz | Manifest（`types`、`relations`、`permissions`） | YAML，`version: 3` |
| Warrant | 物件型別（`inheritIf`、`rules`） | JSON |

出處：[SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA configuration language](https://openfga.dev/docs/configuration-language) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## 元組語法

論文將元組寫成 `object#relation@user`，其中使用者本身可以是使用者集合 `object#relation`（§2.1）。下表各列在文件提供字串形式的情況下，展示 Beto 所屬群組作為 readme 檢視者的寫法。

| 系統 | 名稱 | 形式 |
| --- | --- | --- |
| 論文 | Relation tuple（關係元組） | `doc:readme#viewer@group:eng#member` |
| SpiceDB | Relationship | `doc:readme#viewer@group:eng#member` |
| OpenFGA | Relationship tuple | user `group:eng#member`、relation `viewer`、object `doc:readme` |
| Permify | Relational tuple | `doc:readme#viewer@group:eng#member` |
| Ory Keto | Relation tuple | `Doc:readme#viewers@Group:eng#members` |
| Topaz | Relation | 欄位 `object_type`、`object_id`、`relation`、`subject_type`、`subject_id`，以及選擇性的 `subject_relation` |
| Warrant | Warrant | `[user:1] is an [editor] of [document:docA]`（README 的範例） |

出處：[SpiceDB relationships](https://authzed.com/docs/spicedb/concepts/relationships) · [OpenFGA concepts](https://openfga.dev/docs/concepts) · [Permify sync data](https://fusionauth.io/permify-docs/getting-started/sync-data) · [Ory Keto relation tuples](https://www.ory.com/docs/keto/concepts/relation-tuples) · [Topaz `common.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/common/v3/common.proto) · [Warrant README](https://github.com/warrant-dev/warrant)

## 改寫運算子

論文的改寫規則以聯集、交集與排除組合三種葉節點：`_this`、`computed_userset` 與 `tuple_to_userset`（§2.3.1）。

| 系統 | 聯集／交集／排除 | computed_userset | tuple_to_userset |
| --- | --- | --- | --- |
| 論文 | `union` / `intersection` / `exclusion` | `computed_userset` | `tuple_to_userset` |
| SpiceDB | `+` / `&` / `-` | 指名一個關係或權限 | `parent->view`（另有 `.any()`；`.all()` 取交集） |
| OpenFGA | `or` / `and` / `but not` | 直接寫關係名稱 | `viewer from parent` |
| Permify | `or` / `and` / `not` | 直接寫名稱 | 點號：`org.admin` |
| Ory Keto | `\|\|` / `&&` / `!` | `this.permits.x(ctx)` | `.traverse(...)` |
| Topaz | `\|` / `&` / `-` | 指名一個關係或權限 | `parent->can_read` |
| Warrant | `anyOf` / `allOf` / `noneOf` | `inheritIf` | `ofType` + `withRelation` |

出處：[SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA equivalent Zanzibar concepts](https://openfga.dev/docs/configuration-language#equivalent-zanzibar-concepts) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## 一致性權杖與模式

論文的 zookie 是 "an opaque byte sequence encoding a globally meaningful timestamp"（一個不透明的位元組序列，編碼了一個具全域意義的時間戳記）（§2.4）；檢查會在不早於其所攜帶之 zookie 的快照上評估（§2.2、§2.4.4）。

| 系統 | 權杖 | 模式或行為 |
| --- | --- | --- |
| 論文 | Zookie | 有 zookie：至少一樣新；沒有：「相當新的快照」（"a reasonably recent snapshot"）（§2.4.1） |
| SpiceDB | ZedToken | `minimize_latency`、`at_least_as_fresh`、`at_exact_snapshot`、`fully_consistent` |
| OpenFGA | 無 | `MINIMIZE_LATENCY`（預設）、`HIGHER_CONSISTENCY`；快取預設關閉 |
| Permify | Snap Token | 由 Write 傳回，以 `snap_token` 傳給 Check；沒有時使用最新的交易 |
| Ory Keto | `snaptoken` 欄位 | "not implemented yet and has no effect"（尚未實作，沒有作用） |
| Topaz | 文件中未記載 | reader API 中沒有權杖欄位 |
| Warrant | `Warrant-Token` 標頭 | 開源伺服器不傳回權杖，只會對 `latest` 作出反應，即把讀取送往主資料庫 |

出處：[SpiceDB consistency](https://authzed.com/docs/spicedb/concepts/consistency) · [OpenFGA consistency](https://openfga.dev/docs/interacting/consistency) · [Permify snap tokens](https://fusionauth.io/permify-docs/operations/snap-tokens) · [Keto `check_service.proto`](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto) · [Topaz `reader.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/reader/v3/reader.proto) · [Warrant `wookie.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/wookie/wookie.go)、[`sql.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/database/sql.go)、[`warrant/service.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/service.go)

## Watch 與變更日誌

論文的 Watch 從變更日誌串流傳送元組變更，並以心跳 zookie 作為繼續的起點（§2.4.3、§3）。

| 系統 | API | 形式 |
| --- | --- | --- |
| 論文 | Watch | 串流，可用 zookie 繼續 |
| SpiceDB | `Watch` | 串流，可用 ZedToken（`changes_through`）繼續 |
| OpenFGA | `ReadChanges` | 以接續權杖分頁讀取（輪詢） |
| Permify | `Watch` | 串流（`stream WatchResponse`） |
| Ory Keto | 無 | protocol 檔案中沒有 watch 服務 |
| Topaz | 無 | protocol 檔案中沒有 watch 服務 |
| Warrant | 無 | 儲存庫中沒有變更或事件端點 |

出處：[SpiceDB `watch_service.proto`](https://github.com/authzed/api/blob/main/authzed/api/v1/watch_service.proto) · [OpenFGA `openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto) · [Permify `service.proto`](https://github.com/Permify/permify/blob/master/proto/base/v1/service.proto) · [Keto protos](https://github.com/ory/keto/tree/master/proto/ory/keto) · [Topaz go-directory protos](https://github.com/aserto-dev/go-directory/tree/main/proto/aserto/directory) · [Warrant repository](https://github.com/warrant-dev/warrant)

## 類似 Leopard 的索引

Leopard 是論文中用於大型且深層巢狀群組的索引，由快照與 Watch 更新建構而成（§3.2.4）。

| 系統 | 預先計算的索引 | 備註 |
| --- | --- | --- |
| 論文 | Leopard | 服務、離線與增量三個部分（§3.2.4） |
| SpiceDB | AuthZed Materialize | 商業功能，供 AuthZed Dedicated 客戶使用；"takes inspiration from the Leopard index component"（從 Leopard 索引元件汲取靈感） |
| OpenFGA | 文件中未記載 | Check 快取與 iterator 快取 |
| Permify | 文件中未記載 | "process-local cache; there is no shared cache layer"（行程本地快取；沒有共用的快取層） |
| Ory Keto | 文件中未記載 | |
| Topaz | 文件中未記載 | |
| Warrant | 文件中未記載 | |

出處：[AuthZed Materialize](https://authzed.com/docs/materialize/getting-started/overview) · [OpenFGA consistency (cache flags)](https://openfga.dev/docs/interacting/consistency) · [Permify cache](https://fusionauth.io/permify-docs/operations/cache) · [Ory Keto docs](https://www.ory.com/docs/keto) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant repository](https://github.com/warrant-dev/warrant)。「文件中未記載」的意思是所列頁面沒有描述這樣的索引，而不是已排除其存在。

## 儲存

論文將元組、設定與變更日誌存放在 Spanner 中（§3、§3.1）。

| 系統 | 資料儲存區 |

| 論文 | Spanner |

| Permify | PostgreSQL、memory |
| Ory Keto | PostgreSQL、MySQL、CockroachDB、SQLite（不適用於正式環境） |
| Topaz | 內嵌 BoltDB |
| Warrant | MySQL、PostgreSQL、SQLite |
