Topaz 是一套以 Go 撰寫的授權服務。它 "uses the Open Policy Agent (OPA) as its decision engine, and provides a built-in directory that is inspired by the Google Zanzibar data model"（使用 Open Policy Agent（OPA）作為其決策引擎，並提供一個受 Google Zanzibar 資料模型啟發的內建目錄）（[README](https://github.com/aserto-dev/topaz)）。決策由 Rego 政策做出；政策可以詢問目錄某個主體與某個物件之間是否成立某個關係或權限，這就是與 Zanzibar 相似的部分。目錄資料 "modeled and stored locally in an embedded database"（在本地建模並儲存於內嵌資料庫中）（同一份 README）。

Topaz 由 Aserto 打造。2025-04-27，Aserto 宣布正在 "sunsetting the Aserto SaaS control plane and will shut it down by May 31, 2025"（逐步淘汰 Aserto SaaS 控制平面，並將於 2025 年 5 月 31 日前關閉），將 "wind down Aserto as a commercial entity"（結束 Aserto 作為商業實體的營運），且 "we have a set of maintainers that will continue to support Topaz"（我們有一群維護者會繼續支援 Topaz）（[Aserto blog](https://www.aserto.com/blog/the-final-chapter-for-aserto)，廠商撰寫）。此後仍持續發布新版本。截至 2026-11-13，預設分支上最近的 30 個 commit 全部出自同一位作者 Gert Drapers，他也是那篇結束營運文章的署名者（[commits](https://github.com/aserto-dev/topaz/commits/main)）。

## 以 Topaz manifest 表示貫穿全站的範例

論文的圖 1 讓擁有者成為編輯者、編輯者成為檢視者，並讓上層資料夾的檢視者成為文件的檢視者（§2.3.1）。Topaz manifest 將存放儲存紀錄的 `relations`，與由 relation 及其他 permission 計算而來的 `permissions` 分開。

```yaml
model:
  version: 3

types:
  user: {}

  group:
    relations:
      member: user

  folder:
    relations:
      viewer: user | group#member
    permissions:
      can_read: viewer

  doc:
    relations:
      parent: folder
      owner: user
      editor: user | group#member
      viewer: user | group#member
    permissions:
      can_write: owner | editor
      can_read: viewer | can_write | parent->can_read
```

`group#member` 將該 relation 授予 "everyone with the `member` relation to a specified `group`"（與指定 `group` 具有 `member` 關係的所有人），而箭頭 "allows a permission to be granted to subjects who have a specified relation or permission with another object"（允許將權限授予與另一個物件具有指定關係或權限的主體）（[manifest reference](https://www.topaz.sh/docs/directory/manifest-reference)）。名稱必須為小寫，且最多 64 個字元。

- "The Authorizer exposes three APIs to the calling application"（授權器向呼叫它的應用程式提供三個 API）：`authz/is`、`authz/query` 與 `authz/decisiontree`，每一個都是 "a POST or gRPC API"（POST 或 gRPC API）（[architecture](https://www.topaz.sh/docs/architecture)）。
- 政策透過 OPA 內建函式存取目錄，包括 `ds.check`、`ds.check_relation` 與 `ds.check_permission`（同一頁面）。
- "The directory is implemented as a BoltDB instance"（目錄以一個 BoltDB 實例實作）（同一頁面）。"Directory objects are loaded on-demand, in contrast to `data.json` files"（目錄物件是依需求載入的，這與 `data.json` 檔案不同），後者是隨政策一起載入的。
- "The authorizer captures and stores decision logs for every decision that it evaluates"（授權器會為它評估的每一個決策擷取並儲存決策日誌）（同一頁面）。
- Topaz 可以部署為 "as a sidecar or a microservice in your cloud"（你雲端中的 sidecar 或微服務）（[intro](https://www.topaz.sh/docs/intro)）。

## 一致性

論文的 zookie 讓客戶端可以要求在 "at a consistent snapshot no earlier than the given zookie"（不早於給定 zookie 的一致性快照上）進行檢查（§2.4.4）。Topaz 沒有記載任何可比較的東西：manifest reference 與 architecture 頁面對一致性沒有任何陳述，而目錄的 Reader 與 Writer 訊息也沒有任何權杖或快照欄位（[reader.proto](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/reader/v3/reader.proto)、[writer.proto](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/writer/v3/writer.proto)）。檢查讀取的是它所在之 Topaz 實例的 BoltDB 檔案。此處查核的頁面並未說明多個實例如何共用或複製資料。

## 與論文的差異

- **以政策為先。** 決策 API 是 `Is`，它評估一條 Rego 政策；Zanzibar 風格的檢查只是政策可以使用的一項輸入。在論文中，對使用者集合的 Check 本身就是決策（§2.4.4）。
- **本地內嵌儲存。** 每個實例一個 BoltDB 檔案，而非複製到全球的 Spanner（§3.1）。
- **沒有 zookie、Watch 或 Leopard。** 文件中皆未記載。
- **萬用字元。** `viewer: user | user:*` 允許對 ID 為 `*` 的主體建立 relation（[manifest reference](https://www.topaz.sh/docs/directory/manifest-reference)）。
- **決策日誌。** 每一個決策都會為稽核而記錄，論文並未為 Zanzibar 描述這一點。
