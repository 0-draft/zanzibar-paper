Plusieurs projets open source se présentent comme inspirés de Zanzibar ou modelés sur lui. Cette page en confronte six à l’article, un aspect par tableau. Les cellules sont brèves ; les sources de chaque ligne sont indiquées sous chaque tableau. Les faits ont été vérifiés le 2026-11-13 et proviennent du dépôt et de la documentation de chaque projet ; la plupart sont donc rédigés par l’éditeur lui-même.

Les six : [SpiceDB](https://github.com/authzed/spicedb) (AuthZed), [OpenFGA](https://github.com/openfga/openfga) (CNCF), [Permify](https://github.com/Permify/permify) (FusionAuth), [Ory Keto](https://github.com/ory/keto) (Ory), [Topaz](https://github.com/aserto-dev/topaz) (ses mainteneurs, après la cessation d’activité d’Aserto) et [Warrant](https://github.com/warrant-dev/warrant) (WorkOS). Chacun a sa propre page : [SpiceDB](../spicedb/), [OpenFGA](../openfga/), [Permify](../permify/), [Ory Keto](../ory-keto/), [Topaz](../topaz/), [Warrant](../warrant/).

## Langage de schéma

L’article parle de configuration d’espace de noms : des relations dotées de règles de réécriture de userset (§2.3). La figure 1 en écrit une dans une syntaxe textuelle de type protocol buffer ; l’article ne nomme pas le format.

| Système | Langage de schéma | Format |
| --- | --- | --- |
| Article | Configuration d’espace de noms | Texte de type Protobuf dans la figure 1 (format non nommé) |
| SpiceDB | Schema (`definition`, `relation`, `permission`) | Langage propre |
| OpenFGA | Authorization model (`type`, `define`) | DSL, compilé en JSON |
| Permify | Permify Schema (`entity`, `relation`, `permission` / `action`, `attribute`, `rule`) | Langage propre |
| Ory Keto | Ory Permission Language (OPL) | Sous-ensemble de TypeScript |
| Topaz | Manifest (`types`, `relations`, `permissions`) | YAML, `version: 3` |
| Warrant | Types d’objets (`inheritIf`, `rules`) | JSON |

Sources : [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA configuration language](https://openfga.dev/docs/configuration-language) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## Syntaxe des tuples

L’article écrit un tuple sous la forme `object#relation@user`, où l’utilisateur peut lui-même être un userset `object#relation` (§2.1). Les lignes ci-dessous montrent le groupe de Beto en tant que lecteurs du readme, lorsque la documentation donne une forme textuelle.

| Système | Nom | Forme |
| --- | --- | --- |
| Article | Relation tuple (tuple de relation) | `doc:readme#viewer@group:eng#member` |
| SpiceDB | Relationship | `doc:readme#viewer@group:eng#member` |
| OpenFGA | Relationship tuple | user `group:eng#member`, relation `viewer`, object `doc:readme` |
| Permify | Relational tuple | `doc:readme#viewer@group:eng#member` |
| Ory Keto | Relation tuple | `Doc:readme#viewers@Group:eng#members` |
| Topaz | Relation | Champs `object_type`, `object_id`, `relation`, `subject_type`, `subject_id`, `subject_relation` facultatif |
| Warrant | Warrant | `[user:1] is an [editor] of [document:docA]` (exemple du README) |

Sources : [SpiceDB relationships](https://authzed.com/docs/spicedb/concepts/relationships) · [OpenFGA concepts](https://openfga.dev/docs/concepts) · [Permify sync data](https://fusionauth.io/permify-docs/getting-started/sync-data) · [Ory Keto relation tuples](https://www.ory.com/docs/keto/concepts/relation-tuples) · [Topaz `common.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/common/v3/common.proto) · [Warrant README](https://github.com/warrant-dev/warrant)

## Opérateurs de réécriture

Les règles de réécriture de l’article combinent trois feuilles, `_this`, `computed_userset` et `tuple_to_userset`, par l’union, l’intersection et l’exclusion (§2.3.1).

| Système | Union / intersection / exclusion | computed_userset | tuple_to_userset |
| --- | --- | --- | --- |
| Article | `union` / `intersection` / `exclusion` | `computed_userset` | `tuple_to_userset` |
| SpiceDB | `+` / `&` / `-` | Nommer une relation ou une permission | `parent->view` (également `.any()` ; `.all()` calcule une intersection) |
| OpenFGA | `or` / `and` / `but not` | Nom de relation seul | `viewer from parent` |
| Permify | `or` / `and` / `not` | Nom seul | Point : `org.admin` |
| Ory Keto | `\|\|` / `&&` / `!` | `this.permits.x(ctx)` | `.traverse(...)` |
| Topaz | `\|` / `&` / `-` | Nommer une relation ou une permission | `parent->can_read` |
| Warrant | `anyOf` / `allOf` / `noneOf` | `inheritIf` | `ofType` + `withRelation` |

Sources : [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA equivalent Zanzibar concepts](https://openfga.dev/docs/configuration-language#equivalent-zanzibar-concepts) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## Jeton de cohérence et modes

Le zookie de l’article est « an opaque byte sequence encoding a globally meaningful timestamp » (une séquence d’octets opaque encodant un horodatage ayant un sens global) (§2.4) ; une vérification est évaluée sur un instantané qui n’est pas antérieur au zookie qu’elle transporte (§2.2, §2.4.4).

| Système | Jeton | Modes ou comportement |
| --- | --- | --- |
| Article | Zookie | Avec zookie : au moins aussi frais ; sans : « a reasonably recent snapshot » (un instantané raisonnablement récent) (§2.4.1) |
| SpiceDB | ZedToken | `minimize_latency`, `at_least_as_fresh`, `at_exact_snapshot`, `fully_consistent` |
| OpenFGA | Aucun | `MINIMIZE_LATENCY` (par défaut), `HIGHER_CONSISTENCY` ; cache désactivé par défaut |
| Permify | Snap Token | Renvoyé par Write, transmis à Check sous la forme `snap_token` ; sans jeton, la dernière transaction |
| Ory Keto | Champ `snaptoken` | « not implemented yet and has no effect » (pas encore implémenté et sans effet) |
| Topaz | Aucun documenté | Aucun champ de jeton dans l’API reader |
| Warrant | En-tête `Warrant-Token` | Le serveur open source ne renvoie aucun jeton et ne réagit qu’à `latest`, qui envoie la lecture à la base de données primaire |

Sources : [SpiceDB consistency](https://authzed.com/docs/spicedb/concepts/consistency) · [OpenFGA consistency](https://openfga.dev/docs/interacting/consistency) · [Permify snap tokens](https://fusionauth.io/permify-docs/operations/snap-tokens) · [Keto `check_service.proto`](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto) · [Topaz `reader.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/reader/v3/reader.proto) · [Warrant `wookie.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/wookie/wookie.go), [`sql.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/database/sql.go), [`warrant/service.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/service.go)

On remarque que seuls les deux liens en trait plein permettent à une application de demander « au moins aussi frais que mon écriture », ce qui protège contre le problème du « nouvel ennemi » dans l’article (§2.2).

## Watch et journal des modifications

Le Watch de l’article diffuse en flux les modifications de tuples issues d’un journal des modifications, avec des zookies de pulsation permettant de reprendre (§2.4.3, §3).

| Système | API | Forme |
| --- | --- | --- |
| Article | Watch | Flux, reprise possible avec un zookie |
| SpiceDB | `Watch` | Flux, reprise possible avec un ZedToken (`changes_through`) |
| OpenFGA | `ReadChanges` | Lecture paginée avec un jeton de continuation (interrogée périodiquement) |
| Permify | `Watch` | Flux (`stream WatchResponse`) |
| Ory Keto | Aucune | Aucun service watch dans les fichiers de protocole |
| Topaz | Aucune | Aucun service watch dans les fichiers de protocole |
| Warrant | Aucune | Aucun point d’accès de modifications ou d’événements dans le dépôt |

Sources : [SpiceDB `watch_service.proto`](https://github.com/authzed/api/blob/main/authzed/api/v1/watch_service.proto) · [OpenFGA `openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto) · [Permify `service.proto`](https://github.com/Permify/permify/blob/master/proto/base/v1/service.proto) · [Keto protos](https://github.com/ory/keto/tree/master/proto/ory/keto) · [Topaz go-directory protos](https://github.com/aserto-dev/go-directory/tree/main/proto/aserto/directory) · [Warrant repository](https://github.com/warrant-dev/warrant)

## Index de type Leopard

Leopard est l’index de l’article pour les groupes volumineux et profondément imbriqués, construit à partir d’instantanés et des mises à jour de Watch (§3.2.4).

| Système | Index précalculé | Remarque |
| --- | --- | --- |
| Article | Leopard | Parties service, hors ligne et incrémentale (§3.2.4) |
| SpiceDB | AuthZed Materialize | Commercial, pour les clients d’AuthZed Dedicated ; « takes inspiration from the Leopard index component » (s’inspire du composant d’index Leopard) |
| OpenFGA | Aucun documenté | Caches de Check et d’itérateurs |
| Permify | Aucun documenté | « process-local cache; there is no shared cache layer » (cache local au processus ; il n’y a pas de couche de cache partagée) |
| Ory Keto | Aucun documenté | |
| Topaz | Aucun documenté | |
| Warrant | Aucun documenté | |

Sources : [AuthZed Materialize](https://authzed.com/docs/materialize/getting-started/overview) · [OpenFGA consistency (cache flags)](https://openfga.dev/docs/interacting/consistency) · [Permify cache](https://fusionauth.io/permify-docs/operations/cache) · [Ory Keto docs](https://www.ory.com/docs/keto) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant repository](https://github.com/warrant-dev/warrant). « Aucun documenté » signifie que les pages citées ne décrivent aucun index de ce genre, et non que son existence a été exclue.
