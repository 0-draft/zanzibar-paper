Several open-source projects describe themselves as inspired by or modelled on Zanzibar. This page lines six of them up against the paper, one concern per table. Cells are short; the sources for every row are listed under each table. Facts were checked on 2026-11-13 and come from each project's own repository and documentation, so most are vendor-authored.

The six: [SpiceDB](https://github.com/authzed/spicedb) (AuthZed), [OpenFGA](https://github.com/openfga/openfga) (CNCF), [Permify](https://github.com/Permify/permify) (FusionAuth), [Ory Keto](https://github.com/ory/keto) (Ory), [Topaz](https://github.com/aserto-dev/topaz) (community maintainers, formerly Aserto) and [Warrant](https://github.com/warrant-dev/warrant) (WorkOS). SpiceDB and OpenFGA have their own pages: [SpiceDB](../spicedb/), [OpenFGA](../openfga/).

## Schema language

The paper calls it a namespace configuration: relations with userset rewrite rules, in a protobuf text format (§2.3, Figure 1).

| System | Schema language | Format |
| --- | --- | --- |
| Paper | Namespace config | Protobuf text (Figure 1) |
| SpiceDB | Schema (`definition`, `relation`, `permission`) | Own language |
| OpenFGA | Authorization model (`type`, `define`) | DSL, compiled to JSON |
| Permify | Permify Schema (`entity`, `relation`, `permission` / `action`, `attribute`, `rule`) | Own language |
| Ory Keto | Ory Permission Language (OPL) | TypeScript subset |
| Topaz | Manifest (`types`, `relations`, `permissions`) | YAML, `version: 3` |
| Warrant | Object types (`inheritIf`, `rules`) | JSON |

Sources: [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA configuration language](https://openfga.dev/docs/configuration-language) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## Tuple syntax

The paper writes a tuple as `object#relation@user`, where the user can itself be a userset `object#relation` (§2.1). The rows below show Beto's group being viewers of the readme where the docs give a string form.

| System | Name | Shape |
| --- | --- | --- |
| Paper | Relation tuple | `doc:readme#viewer@group:eng#member` |
| SpiceDB | Relationship | `doc:readme#viewer@group:eng#member` |
| OpenFGA | Relationship tuple | user `group:eng#member`, relation `viewer`, object `doc:readme` |
| Permify | Relational tuple | `doc:readme#viewer@group:eng#member` |
| Ory Keto | Relation tuple | `Group:group1#members@User:user1` (docs' example) |
| Topaz | Relation | Fields `object_type`, `object_id`, `relation`, `subject_type`, `subject_id`, optional `subject_relation` |
| Warrant | Warrant | `[user:1] is an [editor] of [document:docA]` (README's example) |

Sources: [SpiceDB relationships](https://authzed.com/docs/spicedb/concepts/relationships) · [OpenFGA concepts](https://openfga.dev/docs/concepts) · [Permify sync data](https://fusionauth.io/permify-docs/getting-started/sync-data) · [Ory Keto relation tuples](https://www.ory.com/docs/keto/concepts/relation-tuples) · [Topaz `common.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/common/v3/common.proto) · [Warrant README](https://github.com/warrant-dev/warrant)

## Rewrite operators

The paper's rewrite rules combine three leaves, `_this`, `computed_userset` and `tuple_to_userset`, with union, intersection and exclusion (§2.3.1).

| System | Union / intersection / exclusion | computed_userset | tuple_to_userset |
| --- | --- | --- | --- |
| Paper | `union` / `intersection` / `exclusion` | `computed_userset` | `tuple_to_userset` |
| SpiceDB | `+` / `&` / `-` | Name a relation or permission | `parent->view` (also `.any()`; `.all()` intersects) |
| OpenFGA | `or` / `and` / `but not` | Bare relation name | `viewer from parent` |
| Permify | `or` / `and` / `not` | Bare name | Dot: `org.admin` |
| Ory Keto | `\|\|` / `&&` / `!` | `this.permits.x(ctx)` | `.traverse(...)` |
| Topaz | `\|` / `&` / `-` | Name a relation or permission | `parent->can_read` |
| Warrant | `anyOf` / `allOf` / `noneOf` | `inheritIf` | `ofType` + `withRelation` |

Sources: [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA equivalent Zanzibar concepts](https://openfga.dev/docs/configuration-language#equivalent-zanzibar-concepts) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## Consistency token and modes

The paper's zookie is "an opaque byte sequence encoding a globally meaningful timestamp" (§2.4); a check is evaluated at a snapshot no earlier than the zookie it carries (§2.2, §2.4.4).

| System | Token | Modes or behaviour |
| --- | --- | --- |
| Paper | Zookie | With zookie: at least as fresh; without: "a reasonably recent snapshot" (§2.4.1) |
| SpiceDB | ZedToken | `minimize_latency`, `at_least_as_fresh`, `at_exact_snapshot`, `fully_consistent` |
| OpenFGA | None | `MINIMIZE_LATENCY` (default), `HIGHER_CONSISTENCY`; cache off by default |
| Permify | Snap Token | Returned by Write, passed to Check as `snap_token`; without one, the latest transaction |
| Ory Keto | `snaptoken` field | "not implemented yet and has no effect" |
| Topaz | None documented | No token fields in the reader API |
| Warrant | `Warrant-Token` header | Accepts a token or `latest` |

Sources: [SpiceDB consistency](https://authzed.com/docs/spicedb/concepts/consistency) · [OpenFGA consistency](https://openfga.dev/docs/interacting/consistency) · [Permify snap tokens](https://fusionauth.io/permify-docs/operations/snap-tokens) · [Keto `check_service.proto`](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto) · [Topaz `reader.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/reader/v3/reader.proto) · [Warrant `wookie.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/wookie/wookie.go)

## Watch and changelog

The paper's Watch streams tuple changes from a changelog, with heartbeat zookies to resume from (§2.4.3, §3).

| System | API | Shape |
| --- | --- | --- |
| Paper | Watch | Stream, resumable with a zookie |
| SpiceDB | `Watch` | Stream, resumable with a ZedToken (`changes_through`) |
| OpenFGA | `ReadChanges` | Paginated read with a continuation token (polled) |
| Permify | `Watch` | Stream (`stream WatchResponse`) |
| Ory Keto | None | No watch service in the protocol files |
| Topaz | None | No watch service in the protocol files |
| Warrant | None | No change or event endpoint in the repository |

Sources: [SpiceDB `watch_service.proto`](https://github.com/authzed/api/blob/main/authzed/api/v1/watch_service.proto) · [OpenFGA `openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto) · [Permify `service.proto`](https://github.com/Permify/permify/blob/master/proto/base/v1/service.proto) · [Keto protos](https://github.com/ory/keto/tree/master/proto/ory/keto) · [Topaz go-directory protos](https://github.com/aserto-dev/go-directory/tree/main/proto/aserto/directory) · [Warrant repository](https://github.com/warrant-dev/warrant)

## Leopard-like index

Leopard is the paper's index for large and deeply nested groups, built from snapshots and Watch updates (§3.2.4).

| System | Precomputed index | Note |
| --- | --- | --- |
| Paper | Leopard | Serving, offline and incremental parts (§3.2.4) |
| SpiceDB | AuthZed Materialize | Commercial managed service; "takes inspiration from the Leopard index" |
| OpenFGA | None documented | Check and iterator caches |
| Permify | None documented | "process-local cache; there is no shared cache layer" |
| Ory Keto | None documented | |
| Topaz | None documented | |
| Warrant | None documented | |

Sources: [AuthZed Materialize](https://authzed.com/docs/authzed/concepts/authzed-materialize) · [OpenFGA consistency (cache flags)](https://openfga.dev/docs/interacting/consistency) · [Permify cache](https://fusionauth.io/permify-docs/operations/cache) · [Ory Keto docs](https://www.ory.com/docs/keto) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant repository](https://github.com/warrant-dev/warrant). "None documented" means the pages listed describe no such index, not that one was ruled out.

## Storage

The paper stores tuples, configs and the changelog in Spanner (§3, §3.1).

| System | Datastores |
| --- | --- |
| Paper | Spanner |
| SpiceDB | CockroachDB, Cloud Spanner, PostgreSQL, MySQL (not recommended), memdb (development) |
| OpenFGA | memory (default), PostgreSQL, MySQL, SQLite |
| Permify | PostgreSQL, memory |
| Ory Keto | PostgreSQL, MySQL, CockroachDB, SQLite (not for production) |
| Topaz | Embedded BoltDB |
| Warrant | MySQL, PostgreSQL, SQLite |

Sources: [SpiceDB datastores](https://authzed.com/docs/spicedb/concepts/datastores) · [Configure OpenFGA](https://openfga.dev/docs/getting-started/setup-openfga/configure-openfga) · [Permify configuration](https://fusionauth.io/permify-docs/setting-up/configuration) · [Ory deployment](https://www.ory.com/docs/oss/deployment) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant migrations](https://github.com/warrant-dev/warrant/tree/main/migrations/datastore)
