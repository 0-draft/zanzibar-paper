Warrant ist ein in Go geschriebener Autorisierungsdienst. Sein README beschreibt "a relationship based access control (ReBAC) engine (inspired by Google Zanzibar)" (eine Engine für beziehungsbasierte Zugriffskontrolle (ReBAC), inspiriert von Google Zanzibar), die auch rollen- und attributbasierte Regeln abdeckt, und schreibt eine Beziehung als `[user:1] is an [editor] of [document:docA]` ([README](https://github.com/warrant-dev/warrant)). Eine gespeicherte Beziehung heißt *Warrant*.

WorkOS hat Warrant 2024 übernommen. Das Datum, 2024-04-23, stammt aus einem Beitrag von WorkOS auf X ([Beitrag](https://x.com/WorkOS/status/1782774170146791776)): X lieferte die Seite nicht an den Prüfer dieser Website aus, daher wurde das Datum aus der ID des Beitrags dekodiert, und der Text des Beitrags ("Today, we are excited to announce the acquisition of @warrant_dev", also: Heute freuen wir uns, die Übernahme von @warrant_dev bekanntzugeben) wurde nur in einem Suchergebnis gesehen. Es wurde kein Blogbeitrag von WorkOS aus erster Hand gefunden. Die Warrant-Website zeigt nun "Warrant —> Now WorkOS FGA" ([warrant.dev](https://warrant.dev)), und das README verlinkt auf die Dokumentation von WorkOS FGA.

## Das durchgehende Beispiel als Objekttypen

Abbildung 1 des Papers macht Eigentümer zu Bearbeitern, Bearbeiter zu Betrachtern und Betrachter des übergeordneten Ordners zu Betrachtern des Dokuments (§2.3.1). In Warrant listet jeder Objekttyp seine Relationen auf; ein leeres Objekt `{}` bedeutet „nur direkte Warrants“, und `inheritIf` fügt eine Regel hinzu.

```json
[
  { "type": "group", "relations": { "member": {} } },
  { "type": "folder", "relations": { "viewer": {} } },
  {
    "type": "doc",
    "relations": {
      "parent": {},
      "owner": {},
      "editor": { "inheritIf": "owner" },
      "viewer": {
        "inheritIf": "anyOf",
        "rules": [
          { "inheritIf": "editor" },
          { "inheritIf": "viewer", "ofType": "folder", "withRelation": "parent" }
        ]
      }
    }
  }
]
```

Es gibt keinen Eintrag `user`: Der Server legt in seiner ersten Datenbankmigration einen eingebauten Objekttyp `user` an ([Migration](https://github.com/warrant-dev/warrant/blob/main/migrations/datastore/postgres/000002_create_default_obj_types.up.sql)). Die Regel mit `ofType` und `withRelation` findet die Warrants `doc:readme#parent@folder:…` und prüft `viewer` auf jedem gefundenen Ordner, wie im Prüfcode (`getMatchingSubjectsBySubjectType` in [check/service.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/check/service.go)).

<Callout title="Gegen den Code geprüft, nicht ausgeführt">
Diese Objekttypen folgen der Struktur, die der Open-Source-Server mit Stand 2026-11-13 akzeptiert: dem Typ `RelationRule` in [spec.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go) und den Testfixtures der Maintainer wie [tests/v2/authz.json](https://github.com/warrant-dev/warrant/blob/main/tests/v2/authz.json). Sie wurden nicht an einen Warrant-Server gesendet. WorkOS FGA, das Produkt, das Warrant weiterführt, wird anders konfiguriert (siehe Status).
</Callout>

Die fünf Warrants des durchgehenden Beispiels als Bodies für `POST /v2/warrants`:

```json
{ "objectType": "doc", "objectId": "readme", "relation": "owner", "subject": { "objectType": "user", "objectId": "anne" } }
{ "objectType": "group", "objectId": "eng", "relation": "member", "subject": { "objectType": "user", "objectId": "beto" } }
{ "objectType": "doc", "objectId": "readme", "relation": "viewer", "subject": { "objectType": "group", "objectId": "eng", "relation": "member" } }
{ "objectType": "doc", "objectId": "readme", "relation": "parent", "subject": { "objectType": "folder", "objectId": "A" } }
{ "objectType": "folder", "objectId": "A", "relation": "viewer", "subject": { "objectType": "user", "objectId": "chen" } }
```

- Ein Go-Dienst bedient die HTTP-API ([router.go](https://github.com/warrant-dev/warrant/blob/main/pkg/service/router.go)).
- Konfigurationen für MySQL und PostgreSQL nehmen einen `dsn` und einen optionalen `readerDsn` ([config.go](https://github.com/warrant-dev/warrant/blob/main/pkg/config/config.go)); auch SQLite wird unterstützt, "in-memory or file" (im Arbeitsspeicher oder als Datei) ([README](https://github.com/warrant-dev/warrant)).
- Die Regel für die Wahl eines Pools ist ein Kommentar in [sql.go](https://github.com/warrant-dev/warrant/blob/main/pkg/database/sql.go): den Writer verwenden, wenn der Aufruf ein Schreibvorgang ist, wenn es keinen Reader gibt, wenn der Kontext "contains 'latest' wookie" (einen „latest“-Wookie enthält) oder wenn Code im Server eine Writer-Überschreibung gesetzt hat; andernfalls den Reader verwenden.

## Konsistenz

Der Code von Warrant nennt sein Token einen *Wookie* ([wookie](https://github.com/warrant-dev/warrant/tree/main/pkg/wookie)). Ein Typ `Token` enthält eine ID, eine Version und einen Zeitstempel, aber der Open-Source-Server sendet nie eines an den Client: Der Warrant-Dienst gibt an dieser Stelle `nil` zurück, und die HTTP-Handler ignorieren es ([warrant/service.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/service.go), [warrant/handlers.go](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/handlers.go)). Was der Server tatsächlich liest, ist der Anfrage-Header `Warrant-Token`, und nur ein Wert ändert das Verhalten: `latest`.

Das README selbst sagt, dass niedrige Latenz bei hohem Durchsatz "requires running Warrant as a distributed service with the use of Warrant-Tokens (also referred to as Zookies in Google Zanzibar)" (erfordert, Warrant als verteilten Dienst mit Warrant-Tokens zu betreiben (in Google Zanzibar auch Zookies genannt)), und dass "this open source version of Warrant is only capable of handling low-to-moderate throughput" (diese Open-Source-Version von Warrant nur niedrigen bis mittleren Durchsatz bewältigen kann) ([README](https://github.com/warrant-dev/warrant), vom Hersteller verfasst). Sein Link zu Warrant-Tokens führt inzwischen zur allgemeinen Übersicht von WorkOS FGA, die sie nicht beschreibt.

Beachten Sie den Unterschied zum Paper. Ein zookie setzt eine Untergrenze, die es Zanzibar erlaubt, "to choose any timestamp fresher than the one encoded in a zookie" (jeden Zeitstempel zu wählen, der aktueller ist als der in einem zookie kodierte) und die meisten Prüfungen "at a default staleness with already replicated data" (mit einer Standard-Veraltung auf bereits replizierten Daten) zu bedienen (§2.2). `latest` enthält keinen Zeitpunkt: Es verlegt den Lesevorgang auf die primäre Datenbank, die die aktuellste Kopie ist, aber das Replikat aufgibt.

## Unterschiede zum Paper

- **Keine Snapshot-Tokens** im Open-Source-Server, wie oben.
- **RBAC und ABAC eingebaut.** Eingebaute Objekttypen für Rollen, Berechtigungen, Mandanten, Preisstufen und Features sowie Richtlinienbedingungen an Warrants ([README](https://github.com/warrant-dev/warrant), [Migration](https://github.com/warrant-dev/warrant/blob/main/migrations/datastore/postgres/000002_create_default_obj_types.up.sql)).
- **Eine Abfragesprache.** `GET /v2/query` beantwortet Listenfragen, die Read und Expand des Papers nicht beantworten ([Query-Handler](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/query/handlers.go)).
- **Kein Watch, kein Expand, kein Leopard**, und eine einzige primäre SQL-Datenbank statt Spanner (§3.1).

- Open Source: erstes Release v0.1.0 am 2023-02-23; letztes Release v1.15.1 am 2024-06-10; letzter Commit am 2025-12-05, eine Änderung am README; nicht archiviert; etwa 1.300 Sterne ([Releases](https://github.com/warrant-dev/warrant/releases), GitHub-API, 2026-11-13).

Sie stellt FGA als Erweiterung von WorkOS RBAC dar: "You configure resource types in the WorkOS Dashboard" (Sie konfigurieren Ressourcentypen im WorkOS-Dashboard), und FGA "can be adopted incrementally, with no data migration or confusing schema DSL" (kann schrittweise eingeführt werden, ohne Datenmigration oder verwirrende Schema-DSL) ([WorkOS-FGA-Dokumentation](https://workos.com/docs/fga), vom Hersteller verfasst). Das Objekttyp-JSON auf dieser Seite ist das Open-Source-Format, nicht das von WorkOS FGA.
