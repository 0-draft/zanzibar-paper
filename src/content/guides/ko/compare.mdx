여러 오픈 소스 프로젝트가 Zanzibar에서 영감을 받았거나 Zanzibar를 본떠 만들었다고 스스로를 소개한다. 이 페이지는 그중 여섯 개를 관심사 하나당 표 하나씩 논문과 나란히 놓는다. 칸은 짧게 썼고, 모든 행의 출처는 각 표 아래에 나열했다. 사실은 2026-11-13에 확인했으며 각 프로젝트 자신의 저장소와 문서에서 왔으므로, 대부분은 벤더가 작성한 것이다.

여섯 개는 [SpiceDB](https://github.com/authzed/spicedb)(AuthZed), [OpenFGA](https://github.com/openfga/openfga)(CNCF), [Permify](https://github.com/Permify/permify)(FusionAuth), [Ory Keto](https://github.com/ory/keto)(Ory), [Topaz](https://github.com/aserto-dev/topaz)(Aserto가 사업을 접은 뒤 그 메인테이너들), [Warrant](https://github.com/warrant-dev/warrant)(WorkOS)다. 각각 별도 페이지가 있다. [SpiceDB](../spicedb/), [OpenFGA](../openfga/), [Permify](../permify/), [Ory Keto](../ory-keto/), [Topaz](../topaz/), [Warrant](../warrant/).

## 스키마 언어

논문은 이를 네임스페이스 설정이라고 부른다. 유저셋 재작성 규칙을 가진 관계들이다(§2.3). 그림 1은 이를 프로토콜 버퍼 스타일의 텍스트 문법으로 쓴다. 논문은 그 형식의 이름을 밝히지 않는다.

| 시스템 | 스키마 언어 | 형식 |
| --- | --- | --- |
| 논문 | 네임스페이스 설정 | 그림 1의 Protobuf 스타일 텍스트(형식 이름 없음) |
| SpiceDB | 스키마(`definition`, `relation`, `permission`) | 자체 언어 |
| OpenFGA | 인가 모델(`type`, `define`) | DSL, JSON으로 컴파일 |
| Permify | Permify Schema(`entity`, `relation`, `permission` / `action`, `attribute`, `rule`) | 자체 언어 |
| Ory Keto | Ory Permission Language (OPL) | TypeScript 부분 집합 |
| Topaz | 매니페스트(`types`, `relations`, `permissions`) | YAML, `version: 3` |
| Warrant | 객체 타입(`inheritIf`, `rules`) | JSON |

출처: [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA configuration language](https://openfga.dev/docs/configuration-language) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## 튜플 문법

논문은 튜플을 `object#relation@user`로 쓰며, 사용자 자리는 그 자체가 유저셋 `object#relation`일 수 있다(§2.1). 아래 행들은 문서가 문자열 형태를 제시하는 경우, Beto의 그룹이 readme의 열람자인 것을 보여 준다.

| 시스템 | 이름 | 형태 |
| --- | --- | --- |
| 논문 | 관계 튜플(relation tuple) | `doc:readme#viewer@group:eng#member` |
| SpiceDB | Relationship | `doc:readme#viewer@group:eng#member` |
| OpenFGA | Relationship tuple | user `group:eng#member`, relation `viewer`, object `doc:readme` |
| Permify | Relational tuple | `doc:readme#viewer@group:eng#member` |
| Ory Keto | Relation tuple | `Doc:readme#viewers@Group:eng#members` |
| Topaz | Relation | 필드 `object_type`, `object_id`, `relation`, `subject_type`, `subject_id`, 선택적 `subject_relation` |
| Warrant | Warrant | `[user:1] is an [editor] of [document:docA]`(README의 예) |

출처: [SpiceDB relationships](https://authzed.com/docs/spicedb/concepts/relationships) · [OpenFGA concepts](https://openfga.dev/docs/concepts) · [Permify sync data](https://fusionauth.io/permify-docs/getting-started/sync-data) · [Ory Keto relation tuples](https://www.ory.com/docs/keto/concepts/relation-tuples) · [Topaz `common.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/common/v3/common.proto) · [Warrant README](https://github.com/warrant-dev/warrant)

## 재작성 연산자

논문의 재작성 규칙은 세 가지 리프 `_this`, `computed_userset`, `tuple_to_userset`을 합집합, 교집합, 차집합으로 결합한다(§2.3.1).

| 시스템 | 합집합 / 교집합 / 차집합 | computed_userset | tuple_to_userset |
| --- | --- | --- | --- |
| 논문 | `union` / `intersection` / `exclusion` | `computed_userset` | `tuple_to_userset` |
| SpiceDB | `+` / `&` / `-` | 관계나 권한의 이름 | `parent->view`(`.any()`도 있음, `.all()`은 교집합) |
| OpenFGA | `or` / `and` / `but not` | 관계 이름 그대로 | `viewer from parent` |
| Permify | `or` / `and` / `not` | 이름 그대로 | 점: `org.admin` |
| Ory Keto | `\|\|` / `&&` / `!` | `this.permits.x(ctx)` | `.traverse(...)` |
| Topaz | `\|` / `&` / `-` | 관계나 권한의 이름 | `parent->can_read` |
| Warrant | `anyOf` / `allOf` / `noneOf` | `inheritIf` | `ofType` + `withRelation` |

출처: [SpiceDB schema](https://authzed.com/docs/spicedb/concepts/schema) · [OpenFGA equivalent Zanzibar concepts](https://openfga.dev/docs/configuration-language#equivalent-zanzibar-concepts) · [Permify modeling](https://fusionauth.io/permify-docs/getting-started/modeling) · [Ory Permission Language](https://www.ory.com/docs/keto/reference/ory-permission-language) · [Topaz manifest reference](https://www.topaz.sh/docs/directory/manifest-reference) · [Warrant `spec.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/objecttype/spec.go)

## 일관성 토큰과 모드

논문의 zookie는 "an opaque byte sequence encoding a globally meaningful timestamp"(전역적으로 의미 있는 타임스탬프를 인코딩한 불투명한 바이트 시퀀스)다(§2.4). 검사는 그것이 담은 zookie보다 이르지 않은 스냅샷에서 평가된다(§2.2, §2.4.4).

| 시스템 | 토큰 | 모드 또는 동작 |
| --- | --- | --- |
| 논문 | zookie | zookie가 있으면: 최소한 그만큼은 최신. 없으면: "a reasonably recent snapshot"(적당히 최근의 스냅샷)(§2.4.1) |
| SpiceDB | ZedToken | `minimize_latency`, `at_least_as_fresh`, `at_exact_snapshot`, `fully_consistent` |
| OpenFGA | 없음 | `MINIMIZE_LATENCY`(기본값), `HIGHER_CONSISTENCY`. 캐시는 기본적으로 꺼짐 |
| Permify | Snap Token | Write가 반환하고 Check에 `snap_token`으로 전달. 없으면 최신 트랜잭션 |
| Ory Keto | `snaptoken` 필드 | "not implemented yet and has no effect"(아직 구현되지 않았으며 효과가 없다) |
| Topaz | 문서화된 것 없음 | reader API에 토큰 필드 없음 |
| Warrant | `Warrant-Token` 헤더 | 오픈 소스 서버는 토큰을 반환하지 않으며 `latest`에만 반응하고, 이는 읽기를 주 데이터베이스로 보낸다 |

출처: [SpiceDB consistency](https://authzed.com/docs/spicedb/concepts/consistency) · [OpenFGA consistency](https://openfga.dev/docs/interacting/consistency) · [Permify snap tokens](https://fusionauth.io/permify-docs/operations/snap-tokens) · [Keto `check_service.proto`](https://github.com/ory/keto/blob/master/proto/ory/keto/relation_tuples/v1alpha2/check_service.proto) · [Topaz `reader.proto`](https://github.com/aserto-dev/go-directory/blob/main/proto/aserto/directory/reader/v3/reader.proto) · [Warrant `wookie.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/wookie/wookie.go), [`sql.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/database/sql.go), [`warrant/service.go`](https://github.com/warrant-dev/warrant/blob/main/pkg/authz/warrant/service.go)

## Watch와 변경 로그

논문의 Watch는 변경 로그로부터 튜플 변경을 스트리밍하며, 재개 지점으로 하트비트 zookie를 쓴다(§2.4.3, §3).

| 시스템 | API | 형태 |
| --- | --- | --- |
| 논문 | Watch | 스트림, zookie로 재개 가능 |
| SpiceDB | `Watch` | 스트림, ZedToken(`changes_through`)으로 재개 가능 |
| OpenFGA | `ReadChanges` | 연속 토큰을 쓰는 페이지 단위 읽기(폴링) |
| Permify | `Watch` | 스트림(`stream WatchResponse`) |
| Ory Keto | 없음 | 프로토콜 파일에 watch 서비스 없음 |
| Topaz | 없음 | 프로토콜 파일에 watch 서비스 없음 |
| Warrant | 없음 | 저장소에 변경이나 이벤트 엔드포인트 없음 |

출처: [SpiceDB `watch_service.proto`](https://github.com/authzed/api/blob/main/authzed/api/v1/watch_service.proto) · [OpenFGA `openfga_service.proto`](https://github.com/openfga/api/blob/main/openfga/v1/openfga_service.proto) · [Permify `service.proto`](https://github.com/Permify/permify/blob/master/proto/base/v1/service.proto) · [Keto protos](https://github.com/ory/keto/tree/master/proto/ory/keto) · [Topaz go-directory protos](https://github.com/aserto-dev/go-directory/tree/main/proto/aserto/directory) · [Warrant repository](https://github.com/warrant-dev/warrant)

## Leopard 같은 인덱스

Leopard는 크고 깊게 중첩된 그룹을 위한 논문의 인덱스로, 스냅샷과 Watch 갱신으로 구축된다(§3.2.4).

| 시스템 | 미리 계산된 인덱스 | 비고 |
| --- | --- | --- |
| 논문 | Leopard | 서빙, 오프라인, 증분 부분(§3.2.4) |
| SpiceDB | AuthZed Materialize | 상용, AuthZed Dedicated 고객용. "takes inspiration from the Leopard index component"(Leopard 인덱스 구성 요소에서 영감을 얻었다) |
| OpenFGA | 문서화된 것 없음 | Check 캐시와 반복자 캐시 |
| Permify | 문서화된 것 없음 | "process-local cache; there is no shared cache layer"(프로세스 로컬 캐시이며 공유 캐시 계층은 없다) |
| Ory Keto | 문서화된 것 없음 | |
| Topaz | 문서화된 것 없음 | |
| Warrant | 문서화된 것 없음 | |

출처: [AuthZed Materialize](https://authzed.com/docs/materialize/getting-started/overview) · [OpenFGA consistency (cache flags)](https://openfga.dev/docs/interacting/consistency) · [Permify cache](https://fusionauth.io/permify-docs/operations/cache) · [Ory Keto docs](https://www.ory.com/docs/keto) · [Topaz architecture](https://www.topaz.sh/docs/architecture) · [Warrant repository](https://github.com/warrant-dev/warrant). "문서화된 것 없음"은 나열한 페이지들이 그런 인덱스를 기술하지 않는다는 뜻이며, 그런 인덱스가 없다고 확인했다는 뜻은 아니다.

## 저장소
